## 1. What This Benchmark Measures

Prior RAGmortem evaluations (`docs/EVIDENCE.md`) used synthetic failure cases generated by the project's own fault injector. This benchmark evaluates the diagnoser on traces derived from a **real-world public dataset**: the SQuAD v1.1 development set (Rajpurkar et al., 2016), which contains genuine Wikipedia passages and human-written questions with known ground-truth answers.

Each trace simulates a complete RAG failure: retrieval was performed with a real BM25 ranker over a 16-passage corpus, a top-8 candidate pool was re-ranked to a top-3 prompt context, and the 'generator' returned an answer. For failure cases the answer is a simulated decoy answer drawn from other questions in the same dataset (wrong by construction; no LLM was called). Ground-truth failure categories are therefore known deterministically and are verified at build time.

## 2. Dataset & Trace Construction

* **Source**: [SQuAD v1.1 development set](https://rajpurkar.github.io/SQuAD-explorer/) (CC BY-SA 4.0).
* **Questions scanned**: 9957 real SQuAD dev questions.
* **Corpus per trace**: 16 real passages (gold evidence + 8 same-article distractors + 7 cross-article distractors).
* **Retriever**: BM25 (k1=1.5, b=0.75), squashed via s/(s+10); candidate pool = top-8, prompt context = top-3.
* **Generator answers**: simulated decoy answers (verified wrong via `is_answer_correct`; no LLM calls).
* **Sample**: 50 failure traces. Selection quota: 8 generation faults, 36 ranking truncations, 6 retrieval misses (natural ranking:retrieval prevalence preserved; generation stratum added explicitly because real LLM traces are unavailable offline).

## 6. Findings

1. **Truncation dominates real retrieval failures.** Across the scanned corpus, 86.2% of real retrieval failures occurred because BM25 surfaced the evidence into the candidate pool but the top-k cut removed it before the prompt. True candidate-pool misses were rare.
2. **Observed mode is deliberately conservative and truncation-biased.** With full candidate-pool telemetry, the candidate-cliff probe attributes most wrong-answer traces to top-k truncation because score tails are flat in real retrieval distributions. Definitive attribution requires reference answers.
3. **Reference-assisted mode isolates the cause.** With ground-truth answers, RAGmortem attributed 100.0% of traces to the correct component, cleanly separating ranking truncation, retrieval misses, and generator failures.
4. **Diagnosis is millisecond-scale**: median 0.135 ms per trace observed, CPU-only, with zero API calls or network access.

## 7. Threats to Validity

* **Simulated generator answers**: real LLM traces were unavailable offline, so wrong answers are decoy answers from the same dataset. Error *style* may differ from production hallucinations.
* **SQuAD is clean single-hop QA**: questions are answerable from one paragraph, and neither the retriever nor the corpus contains OCR noise, chunking artifacts, or multi-hop reasoning.
* **Small corpus per trace**: 16 passages. Retrieval-miss prevalence grows with corpus size; production corpora are far larger.
* **BM25-only runtime retriever**: dense retrievers fail on different query distributions; lexical-gap failure modes are over-represented here relative to hybrid systems.
* **Stratified sample**: the generation stratum is injected by construction and does not represent natural generation-fault prevalence.
* **Local NLI disabled**: `RAGMORTEM_DISABLE_NLI=1` forces deterministic lexical matching; SQuAD answers are verbatim spans, so this is appropriate here but not for paraphrase-heavy production data.
