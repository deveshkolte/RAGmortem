# RAGmortem Competitor Benchmark Simulations

> [!WARNING]
> **SIMULATION NOTICE — NOT REAL TOOLS:**  
> The evaluations in this directory are **simplified behavioral simulations written by the author** in `run_benchmark.py`, **NOT executions of the real third-party libraries or packages**.  
> These simulations model hypothesized theoretical behaviors (e.g. top-k context inspection vs. candidate pool inspection). They were implemented because the corresponding tools either could not be installed (broken wheel on PyPI, unpackageable demo) or represent general metric frameworks rather than discrete failure root-cause classifiers.  
> **These results MUST NOT be cited or published as empirical comparisons against real tools.**

---

## Purpose

To explore structural architectural differences between:
1. **Top-K prompt-only inspection** (evaluating only what reaches the LLM context).
2. **Candidate pool inspection** (evaluating the vector retriever's broader top-$N$ candidate pool before re-ranking and truncation).
3. **Discrete component-level attribution** (retrieval vs. ranking vs. generation vs. abstention).

## Files in this Directory

* **`run_benchmark.py`**: Synthetic test script executing mock predictor functions (`predict_ragas`, `predict_pyvectorhound`, `predict_deepdiag`, `predict_rag_oracle`) against synthetic failure cases.
* **`results.json`**: Simulation outputs generated by `run_benchmark.py`.
* **`results.md`**: Architectural analysis discussing theoretical trade-offs between evaluation paradigms.
* **`mappings.json`**: Conceptual taxonomy mapping between metric names and RAGmortem failure categories.
